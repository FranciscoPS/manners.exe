# Directory Structure

manners.exe is a Unity project. The framework's generic layout (`src/`, `assets/`,
`tests/`) does not apply: Unity compiles only `Assets/` and `Packages/`.

```text
/
├── CLAUDE.md                    # Master configuration (project rules first, then the framework)
├── README.md                    # Architecture, patterns and code rules of the game
├── project.yaml                 # Machine-readable project config — engine, modes, stage
├── .mcp.json                    # Atlassian MCP server (Jira + Confluence)
├── .claude/                     # Agents, skills, hooks, rules, framework docs
├── Assets/                      # CODE ROOT and asset root (Unity)
│   ├── Scripts/                 # Game code by system: Core, Player, Enemy, Combat, Chest,
│   │   │                        #   Overrides, UI (+ UI/Style), Menus, Localization, Camera,
│   │   │                        #   VFX, InvisibleWalls, Sandbox
│   │   └── Editor/              # Editor tools (Tools > Manners menus) and EditMode tests (*Tests.cs)
│   ├── Configurations/          # ScriptableObject data
│   │   ├── Production/          # `_Production` assets; globals under Resources/
│   │   └── Sandbox/             # `_Sandbox` copies wired by SandboxTuning
│   ├── Scenes/                  # MainMenu, Final Levels/LEVEL 1 (Map 1), Sandbox, CityTest;
│   │                            #   MilitaryBase (Map 2) is paused — do not touch
│   ├── Prefabs/                 # Prefabs; UI components under Prefabs/UI/
│   └── Shaders/, Materials/, VFX/, Sprites/, Fonts/, Music/, SFX/, 3DModels/, …
├── Packages/                    # Unity package manifest
├── ProjectSettings/             # Unity settings (EditorBuildSettings, ProjectVersion.txt)
├── Docs/                        # Technical documentation (the framework's `docs/` — same folder
│   │                            #   on Windows and macOS): Performance/, Devlog/, UI_AUTHORING.md
│   ├── engine-reference/unity/  # Version-pinned Unity 6.3 LTS reference
│   ├── architecture/            # ADRs, architecture doc, TR registry (Confluence mirror)
│   └── registry/                # Architecture registry
├── design/                      # Game design documents (Confluence mirror): gdd/, art/, ux/, …
├── production/                  # Production management (Jira mirror + framework state)
│   ├── atlassian.yaml           # Jira/Confluence ids and mappings (committed)
│   ├── epics/                   # Epics and stories mirrored from Jira
│   ├── sprints/                 # Sprint plans mirrored from Jira

│   ├── qa/                      # Bugs (Jira mirror), evidence screenshots, smoke reports

└── Builds/, Library/, Logs/, Temp/, UserSettings/   # Generated by Unity — gitignored
```

## The code root is engine-specific

| `engine.name` | Code root | Why |
|---|---|---|
| **Unity** (this project) | `Assets/` | Unity compiles **only** `Assets/` and `Packages/`. Code outside them is invisible to the compiler. |

**Resolve paths before writing any source file.** A path shown in a framework skill
as `src/…` is a Godot example: read it as *"the code root"* and use `Assets/Scripts/<System>/`.

## Tests

| Kind | Location in this project | Notes |
|---|---|---|
| EditMode | `Assets/Scripts/Editor/*Tests.cs` (`engine.test_root`) | No asmdef: the predefined Editor assembly compiles them and references the Unity Test Framework |
| PlayMode | none yet | A `[UnityTest]` in EditMode can yield `EnterPlayMode` and load `LEVEL 1` |

Read `tests/unit/[system]/` in any framework skill as `Assets/Scripts/Editor/` with a
`[System]Tests.cs` file. Anywhere else the tests are not compiled ("0 tests, Passed").
